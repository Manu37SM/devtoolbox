## How it works

You configure a method, URL, headers, and body, and the request is sent from our server rather than your browser. This is required because browser JavaScript can't send arbitrary cross-origin requests — the target site's CORS policy would block most responses from ever reaching your page. Running the request server-side also means the target site sees our server's IP address rather than yours.

## Common use cases

- Quickly testing an API endpoint without installing a full REST client.
- Checking response headers, status codes, and timing for a request.
- Verifying a webhook or third-party integration returns the expected payload.
